# 거래내역 패널 (F20) — 손익 · 체결내역 · 매매내역

> 문서 지도: [docs/INDEX.md](INDEX.md) · 기준 문서: [PROJECT.md](../PROJECT.md) · 작업 규칙: [CLAUDE.md](../CLAUDE.md) · 개발 순서: [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md)

## 1. 결론 요약

- 상단 바 2행의 **📒 거래내역** 버튼(💰 보유주식 평가금액 오른쪽, ⌘H)으로 여는 **패널**. F18과 같은 방식으로 **메인 영역 위에서 아래로 슬라이딩**하되 **오른쪽에 붙고 폭은 메인의 60%**다. F18(왼쪽 40%)과 **동시에 열려도 겹치지 않는다**(둘이 메인 폭을 40:60으로 나눈다).
- 탭 셋: **손익 · 체결내역 · 매매내역**. 기간은 **일별 · 월별 · 분기별 · 직접 지정**으로 묶고, 시장(전체/국내/미국)·매매구분·종목으로 거른다. 미국 종목은 **외화/원화** 표시를 토글한다.
- 이 패널이 **F2 기간별 손익의 화면**이고, F14의 "주문 내역" 별도 화면을 **체결내역 탭이 대신**한다. F17 매매 통계는 별도 화면이며 패널 바닥에서 연다.
- 원천은 **토스 종료 주문 조회(커서, 100건/페이지)의 로컬 캐시(`broker_order`) + lot 선입선출 매칭(`lot_disposal`)**. 토스 앱이 "잔고(선입선출)"를 쓰므로 lot 소진 순서 FIFO는 [확정]으로 올린다. 숫자는 데몬이 `BigDecimal`로 계산해 문자열로 내려준다.
- 본인 계좌만. 계좌번호는 표시하지 않는다.

## 3. 화면 구성

**머리**: "거래내역" · 탭 [손익 | 체결내역 | 매매내역] · 시장 칩 [전체 | 국내 | 미국] · 통화 토글 [외화 | 원화](미국 포함 시) · 새로고침 · ✕
**기간 줄**: 단위 [일별 | 월별 | 분기별 | 직접] · 범위(시작 ~ 끝, 달력) · 빠른 선택(오늘 · 1주 · 1개월 · 3개월 · 올해 · 1년) · 매매구분 [전체 | 매수 | 매도] · 종목 검색
**바닥 줄**: 출처(토스 종료 주문 조회 캐시 + 선입선출 계산) · 마지막 적재 시각 · "적재 중 N/M" 진행 · [매매 통계(F17) 열기]. 미국 종목이 포함되면 "미국 종목 날짜는 미국 동부시간(ET) 기준" 안내가 붙는다

### 3.1 손익 탭 (F2)

1. **요약 카드**(기간·시장 필터 반영): 실현손익 합계(큰 글씨, 상승 빨강·하락 파랑)와 수익률 → 매매손익 · 환차손익 · 매수금액 · 매도금액 · 수수료·세금 합. 미국 종목은 통화 토글대로 외화/원화 병기.
2. **양도세 손익** 토글 [확정 2026-09-25]: 켜면 요약 카드 아래에 한 줄 카드가 나타나 **양도세 대상 금액**(그 해 해외주식 양도차익 합계 − 기본공제 250만원, 0 미만이면 0)과 **예상 부과액**(대상 금액 × 22% = 양도소득세 20% + 지방소득세 2%)만 간략히 보인다. 연도는 기간 필터와 무관하게 올해 고정(연도 선택 가능). 환율은 결제일 기준환율이 원칙이나 없으면 체결일 환율로 근사하고 "근사"라고 표시한다. 정보 표시이지 세금 계산 서비스가 아니며 "실제 신고는 증권사 자료로" 문구를 붙인다.
3. **목록**(단위별 묶음: 일별이면 날짜, 월별이면 월, 분기별이면 분기): 묶음 머리에 소계(실현손익·수익률·건수) → 행: 종목(국기·이름·코드) · 매도 수량 · 실현손익(외화 / 원화) · 수익률 · 보유 기간 · 출처 칩(MANUAL / AI 추천 / 자동 매수). 정렬: 최신순. 행 클릭 → 종목 전환.

### 3.2 체결내역 탭 (F14 주문 내역)

- 필터 [전체 | 체결 | 미체결]. 미체결은 3번 영역 미체결 탭과 같은 데이터.
- 표(가로 스크롤): 종목명 / 매매구분(매수·매도·매수정정·매도정정·취소) · 주문수량 / 주문단가 · 체결수량 / 체결단가 · 미체결수량 / 수수료·세금 · 주문 시각 / 체결 시각 · 상태 칩(`OrderStatus`) · 출처 칩 · 정정 체인 표시(원주문 ↔ 새 주문을 한 묶음으로, 펼치면 체인 전체).
- 미체결 행에 정정·취소 버튼. 거부(`REJECTED`·`CANCEL_REJECTED`·`AMEND_REJECTED`)는 사유를 툴팁으로.
- 토스는 건별 체결을 주지 않으므로 주문 1건 = 행 1건이다.

### 3.3 매매내역 탭

- 날짜 묶음(단위별) 목록: 종목(국기·이름·코드) · 매수/매도(색) 수량 · 체결금액(외화/원화) · 단가 · 수수료. 묶음 머리에 매수 합·매도 합·건수.
- 체결된 주문만(미체결·취소·거부 제외). 소수점 매도는 수량을 6자리로.
- 손익 탭과 달리 **lot 매칭 없이 체결 그대로**를 보인다(입출금 기록은 토스 API 제공 여부에 따라 [확인 필요]).

## 4. 계산 정의 (데몬, `BigDecimal`, `RoundingMode.HALF_EVEN`)

- **lot 소진 순서 = 선입선출(FIFO)** [확정 2026-09-25, 토스 앱 "잔고(선입선출)"와 일치]. 매도 체결 1건이 여러 lot을 소진하면 `lot_disposal` 행이 lot마다 생긴다.
- 매도 1건의 **외화 실현손익** = Σ_lot (매도단가 − lot 매입단가) × 소진 수량 − 수수료 − 세금.
- **원화 실현손익** = 매도금액 × 매도 시 환율 − Σ_lot 매입원가 × 매입 시 환율(`Lot.fxAtBuy`) − 비용 원화.
  - **매매손익(원화)** = 외화 실현손익 × 매도 시 환율.
  - **환차손익(원화)** = Σ_lot 매입원가(외화) × (매도 시 환율 − 매입 시 환율).
  - 두 값의 합이 원화 실현손익이다(테스트로 강제). 국내 종목은 환차손익 0.
- **수익률** = 실현손익 ÷ Σ 매입원가(같은 통화 기준). 매입원가 0이면 표시 안 함.
- **보유 기간** = 매도 체결 시각 − lot 매수 시각(일 단위 내림).
- **묶음 날짜** [확정 2026-09-25] = 국내 종목은 체결 시각의 **KST** 날짜, 미국 종목은 **미국 동부시간(America/New_York, ET)** 날짜. 미국 종목이 목록에 있으면 기간 줄 끝과 묶음 머리에 "미국 동부시간(ET) 기준" 안내를 표시한다. 시장 "전체"에서는 한 날짜 묶음 안에 두 기준이 섞이므로 묶음 머리에 KST/ET를 각각 적는다. 기간 필터의 시작·끝도 각 시장의 기준 시간대로 해석한다.
- 매도 시 환율은 토스 체결 응답의 환율 필드가 있으면 그 값, 없으면 체결 시각의 `exchange_rate` 캐시(토스 환율 API). 그것도 없으면 **별도 환율 API**(한국은행 ECOS·서울외국환중개 등)를 어댑터로 붙인다 [구현 단계 확정]. 환율이 없으면 원화 값은 "—"로 두고 외화만 보인다.
- **실현손익의 원천은 우리 DB다** [확정 2026-09-25]: 매도 체결이 확정될 때마다(`OrderFilled` → `LotReduced`/`LotClosed`) `lot_disposal` 행을 저장하고, 기간별 손익은 그 행들의 합으로 산출한다. 토스에 기간별 실현손익 API가 있으면 "토스 기준" 값을 나란히 보여 대조만 하고(차이 시 경고 칩), 없어도 기능은 동작한다. API 유무는 구현 단계 학습 테스트에서 확인한다.

## 5. 데이터와 저장

- **원천**: `broker_order`(토스 종료 주문 조회 커서 적재. 기간 시작일이 캐시보다 과거면 뒤로 더 적재하고 진행을 바닥 줄에 표시), `lot`·`lot_disposal`(`LotReduced`·`LotClosed` 이벤트의 projection), `exchange_rate`.
- **새 표 `lot_disposal`** (`docs/DB_SCHEMA.md` 7장, V2, 성격 ②): `disposal_id, user_id, lot_id, broker_order_id, market, code, quantity, sell_price_amount/currency, buy_unit_cost_amount/currency, fee_amount, tax_amount, fx_from, fx_to, fx_rate, fx_as_of(매도 시), realized_amount/currency(외화), realized_krw, fx_pnl_krw, holding_days, lot_origin, disposed_at`. 인덱스 `(user_id, disposed_at)`, `(user_id, market, code, disposed_at)`.
- 요약·묶음 소계는 조회 때 계산한다(4인 규모라 캐시 불필요). 기간이 길고 느리면 월별 소계 캐시를 나중에 둔다.
- 포트: 새 포트 없음. `TradingPort.closedOrders(UserId, cursor)`, `MarketDataPort.exchangeRate`, 이벤트 스토어.
- `LotReduced`·`LotClosed` payload에 `disposal` 정보(매도 주문 id·수량·단가·비용·환율)를 넣는다 → [CORE_DOMAIN.md](CORE_DOMAIN.md) 5·9장 수정 대상.
- 동기화하지 않는다(`LOCAL` 범위, 체결·보유는 각자 API 조회).

## 7. 테스트

- FIFO 매칭: 부분 매도, 여러 lot 소진, 소수점 수량, 같은 시각 두 lot(매수 시각 → lot id 순).
- 원화 실현손익 = 매매손익 + 환차손익(임의 환율 조합), 국내 환차손익 0, 환율 없을 때 원화 미표시.
- 기간 경계: 일별·월별·분기별·직접(시작·끝 포함), KST 날짜 묶음, 고정 `Clock`.
- 정정 체인이 체결내역에서 1묶음, 매매내역에서 최종 체결 1건.
- 화면: 버튼 토글·⌘H·✕·Esc 순서, F18과 동시에 열어도 겹치지 않음(40:60), 종목 변경 시 유지, 행 클릭 종목 전환, 조회 제한 모드 안내.
