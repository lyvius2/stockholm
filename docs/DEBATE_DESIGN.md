# 토론(F6) 설계 — 세 가지 테마, 재개, 기술 방안

작성: 2026-09-22 / 상태: v2 — 실시간 메신저 UI·사용자 개입·재개 규칙 확정 / 관련: `PROJECT.md` 9장 F6, `docs/LLM_ROUTING.md`, `docs/RAG_DESIGN.md`, `docs/MIROFISH_EXPERIMENT_GUIDE.md`

## 1. 확정 사항

- 토론 테마는 세 가지다. **매수 토론**(지금 사도 되는가), **매도 토론**(보유분을 팔 때인가), **산업 동향**(선택한 종목이 속한 산업군 전반의 동향을 분석해 투자 의견 도출). 세 테마 모두 미러피시를 통해 수행할 수 있고, 결론을 내어 의사결정을 돕는다. [확정]
- 종목을 선택하면 **기본 정보와 전망**을 먼저 보여 주고, 토론은 **사용자가 요청할 때** 시작한다. [확정]
- 결론이 난 토론도 **같은 인격(페르소나)들로 나중에 재개**할 수 있다. [확정]
- 화면 배치: 오른쪽 열의 가격 : 토론 = 4 : 6. 상세는 화면 설계 아티팩트. [확정]
- **토론 진행은 메신저 UI로 실시간 표시한다.** 심층(미러피시) 토론도 백그라운드로 돌면서 오가는 대화가 말풍선으로 흐른다. [확정]
- **사용자는 도중에 개입할 수 있다.** 질문, 반박, 동의, 자료 추가, 결론 요청. [확정]
- 전망 요약의 갱신 주기는 **1주**. [확정]
- 재개 시 페르소나 정의가 바뀌었으면 **새 정의로** 간다. [확정]

## 2. 결론부터: RAG로 간다. 파인튜닝은 하지 않는다

"인격들이 기억을 갖고 토론을 이어가며, 최신 자료로 판단한다"는 요구는 **RAG + 구조화된 토론 상태 저장 + 프롬프트 설계**로 구현한다. 파인튜닝은 지금 단계에서 맞지 않고, 이후에도 좁은 용도로만 검토한다. 이유는 다음과 같다.

| 관점 | RAG(+상태 저장) | 파인튜닝 |
|---|---|---|
| 최신성 | 오늘 공시·뉴스가 바로 토론에 들어간다 | 학습 시점에 고정. 시장 정보를 넣을 수 없다 |
| 재개 | 이전 토론 기록을 그대로 다시 넣으면 된다 | 대화 기록을 모델에 넣는 것과 무관. 재개는 어차피 프롬프트로 한다 |
| 표본 | 필요 없음 | 개인이 모을 수 있는 토론·결과 표본은 수백 건. 과적합이 확실하고 검증도 어렵다 |
| 다중 제공자 | 네 제공자 모두 그대로 사용 | 제공자·모델마다 따로 튜닝. 모델이 바뀌면 다시. Claude는 파인튜닝 경로가 제한적 |
| 근거 추적 | 출처 번호로 주장마다 근거를 붙일 수 있다 | 모델 내부에 녹아 근거를 가리킬 수 없다 |
| 비용·시간 | 호출 비용만 | 학습 비용 + 평가 세트 구축 + 회귀 관리 |
| 개인정보 | 자료를 요청 단위로 통제 | 매매 기록을 학습 데이터로 외부에 보내야 한다 |

페르소나의 "성격"은 파인튜닝이 아니라 **페르소나 정의(시스템 프롬프트) + 그 페르소나의 과거 발언·적중 기록(RAG)**로 만든다. 이렇게 하면 페르소나 정의를 사용자가 편집할 수 있고, 모델을 바꿔도 성격이 유지되며, F10의 (페르소나, 모델) 단위 성적 집계와도 맞는다.

**파인튜닝을 검토할 수 있는 유일한 자리.** 2년쯤 뒤, 뉴스 분류·악재 유형 판정·중복 판정 같은 **작고 반복적인 분류 작업**을 로컬 소형 모델(Ollama)에 맡기고 싶을 때, 그 분류기 하나를 LoRA로 튜닝하는 것. 토론·판단에는 쓰지 않는다.

## 3. 세 테마의 정의

| 테마 | 질문 | 시드 자료(RAG 질의) | 결론 형식 | 자동화와의 관계 |
|---|---|---|---|---|
| 매수 | 지금 이 가격에 사도 되는가 | 종목 공시·뉴스(최근 30일), 재무 요약, 밸류에이션, 수급, 직전 토론 결론 | 매수 / 관망 / 매수 금지 + 확신도 + 진입 조건(가격대·분할) | F7 유력 종목 매수 전 "빠른 토론"이 이 테마 |
| 매도 | 보유분을 팔 때인가 | 위 + 본인 보유 단가·기간·수익률(개인 데이터) | 전량 매도 / 일부 매도 / 보유 + 확신도 + 조건 | F8 자동 매도 판단의 자료. `PERSONAL` 등급 |
| 산업 동향 | 이 업종은 어디로 가는가, 그 안에서 이 종목의 위치는 | 업종 뉴스, 동종 종목 공시·실적, 거시 지표(ECOS·FRED), 시장 리포트(F9) | 업종 의견(비중 확대/중립/축소) + 종목의 상대 매력 + 주목할 동종 종목 | F5 추천과 F9 리포트의 입력 |

### 3.1 산업 동향 토론의 동종 종목 범위 [확정]

"같은 업종 코드 전체"는 너무 넓고(코스피 반도체만 수십 종목, 토론 자료가 희석됨), "사용자가 매번 고르기"는 번거롭다. **자동 기본값 + 사용자 편집**을 권한다.

| 단계 | 규칙 |
|---|---|
| 자동 기본값 | 같은 산업 분류(국내: KRX 업종 소분류, 미국: GICS sub-industry 또는 SIC 코드) 안에서 **시가총액 상위 10개**(대상 종목 제외) |
| 자동 추가 | 사용자의 보유·관심 종목 중 같은 분류에 속한 것은 시총과 무관하게 포함 |
| 사용자 편집 | 종목별로 추가·제외. 편집 결과는 저장·동기화되고 다음 토론에도 쓰인다 |
| 확장(후순위) | 사업보고서 "사업의 내용"에서 LLM이 추출한 고객사·공급사·경쟁사를 후보로 제시(가치사슬). 자동 포함하지 않고 제안만 |
| 상한 | 14개. 넘으면 시드 자료가 길어져 토론 품질이 떨어진다 |

산업 분류 코드의 출처: 국내는 종목 마스터(토스 `stocks` 또는 KRX)의 업종 코드, 미국은 SEC EDGAR의 SIC 코드. 분류가 없는 종목(ETF 등)은 사용자 편집만 허용한다.

세 테마는 **같은 페르소나 명단**을 쓰되, 테마별로 사회자의 질문 순서와 결론 스키마가 다르다. 페르소나 명단은 사용자가 편집하며 기본은 가치투자자 · 모멘텀 트레이더 · 리스크 매니저 · 매크로 분석가 · 역발상 투자자 · 사회자.

## 4. 종목 선택 시의 개요·전망

토론을 시작하기 전에 보이는 것.

- **구조화 데이터(LLM 없음)**: 업종, 시총, PER/PBR, 배당수익률, 최근 공시 제목, 종목 상태(경고·정지), 최근 토론 기록 목록.
- **전망 요약(LLM 1회, `DOCUMENT_DIGEST` 목적)**: 최근 자료를 RAG로 모아 5문장 이내로 요약. 출처 번호 필수. **주 1회 자동 갱신**(관심·보유 종목은 주말 배치, 그 밖의 종목은 처음 열 때 생성 후 1주 캐시). 갱신 시각을 화면에 표시하고 "지금 갱신" 버튼을 둔다. 비용이 작은 목적이므로 Ollama가 1순위.
- **동종 종목(권고안, 아래 3.1)**: 개요에 목록으로 보이고 편집할 수 있다.
- 개요는 **결론이 아니다.** "전망 요약"으로 표시하고 확신도를 붙이지 않는다. 확신도는 토론의 산출물에만 붙인다.

## 5. 토론 실행 모델

### 5.1 두 엔진, 한 결과 형식

| | 빠른 토론(자체) | 심층 토론(미러피시) |
|---|---|---|
| 방식 | 페르소나별 LLM 호출(병렬) × 2~3라운드 → 사회자 종합 | 시드 문서 조립 → 미러피시 프로젝트 생성 → 시뮬레이션 → 리포트 회수 |
| 시간 | 1분 안팎 | 수 분 ~ 수십 분, 백그라운드 |
| 페르소나 | 우리 정의를 그대로 사용 | 우리 정의를 시드 문서에 "참여자 프로필"로 넣어 미러피시가 생성하는 에이전트에 반영 (실험으로 반영 정도 확인) |
| 결과 | `Verdict` 레코드 | 리포트 → `STRUCTURED_EXTRACTION`으로 `Verdict` 변환 |

두 엔진 모두 같은 `Verdict`(결론, 확신도, 핵심 근거, 반대 논거, 뒤집을 이벤트, 페르소나별 입장, 인용 문서 ID)를 낸다. 화면과 F10은 엔진을 구분하지 않고 `engine` 필드만 기록한다.

### 5.2 토론 상태의 저장 (재개의 기반)

토론은 이벤트 로그로 저장한다(PROJECT.md 6장과 같은 구조). 하나의 토론(`DebateSession`)은 다음을 가진다.

- 식별: `debateId`, `userId`, 종목, 테마, 엔진
- **페르소나 스냅샷**: 참여 페르소나 각각의 정의 텍스트 **버전**과 배정된 제공자·모델(기록·학습 집계용). **재개 시에는 현재(최신) 정의를 쓴다** — 정의가 바뀌었으면 새 정의로 이어가고, 라운드 기록에 "정의 v3으로 재개"를 남긴다
- **라운드 기록**: 라운드별 페르소나 발언 전문, 인용 문서 ID, 사용 모델·토큰
- **결론 이력**: 결론이 여러 번 나올 수 있다(세션 1 결론, 재개 후 결론 2 …)
- **자료 스냅샷**: 각 라운드에 투입된 RAG 결과의 문서 ID와 `asOf`

### 5.3 실시간 표시와 사용자 개입

**표시.** 토론 창의 "진행 중" 탭은 메신저 형태다. 페르소나 발언은 왼쪽 말풍선(아바타·이름·시각·출처 번호), 사회자는 강조 말풍선, 사용자는 오른쪽 말풍선. 발언을 생성 중인 페르소나는 입력 중 표시(···)로 보인다. 상단 카드에 테마·엔진·라운드·경과 시간, 결론이 나면 결론 카드로 바뀐다.

**전달 경로.** 데몬이 토론 이벤트(`PersonaSpoke`, `UserIntervened`, `RoundEnded`, `VerdictReached`, `EngineStatus`)를 로컬 WebSocket으로 밀어 준다. 빠른 토론은 페르소나별 LLM 스트리밍 응답을 그대로 흘려 말풍선이 글자 단위로 채워지고, 미러피시 심층 토론은 어댑터가 미러피시의 진행 로그·에이전트 발언을 폴링 또는 스트림으로 받아 같은 이벤트로 변환한다(미러피시가 중간 발언을 어떤 형태로 노출하는지는 사전 실험에서 확인 — 리포트만 주고 중간 과정을 안 주면, 심층 토론은 "라운드 요약"만 실시간 표시하고 전문은 완료 후 보여 준다).

**개입.** 사용자는 언제든 입력창으로 끼어든다. 종류는 다섯 가지: 질문, 반박, 동의, 자료 추가(링크·텍스트 → 즉시 RAG 색인 후 이번 토론 자료로 투입), 결론 요청(현재까지로 사회자가 결론). 개입은 `UserIntervened` 이벤트로 기록되어 다음 라운드 프롬프트에 "사용자의 발언"으로 들어가고, **페르소나들은 그 발언에 반드시 응답**한다(사회자가 응답 여부를 확인). 미러피시 심층 토론에서 사용자 개입은 미러피시의 후속 대화(에이전트와의 채팅) 기능으로 전달하고, 지원되지 않으면 우리 쪽 빠른 토론 엔진이 이어받는다.

**개입의 한계.** 사용자 발언도 자료의 하나일 뿐이다. 페르소나가 무조건 동의하도록 프롬프트하지 않고, 사회자는 사용자 주장에 근거가 없으면 "근거 없음"으로 표시한다. 개입은 `Verdict`의 `interventions` 필드에 남아 F10에서 "개입이 결론을 바꿨는가"를 나중에 볼 수 있다.

### 5.4 재개(resume)의 동작

1. 사용자가 기록 탭에서 "재개"를 누른다. 새 토론이 아니라 같은 `debateId`에 라운드가 이어진다. 페르소나는 같은 명단, 정의는 현재 버전.
2. 엔진은 **이전 토론의 압축 요약**(결론, 페르소나별 마지막 입장, 반대 논거)과 **이전 결론 이후 새로 들어온 자료**(`firstSeenAt > 마지막 결론 시각`인 공시·뉴스, 가격 변화, 보유 변화)를 함께 투입한다.
3. 사회자의 첫 질문은 고정이다: **"지난 결론 이후 무엇이 달라졌고, 결론을 바꿔야 하는가."** 페르소나들은 자기 이전 입장을 알고 시작하므로 "입장을 유지/수정"을 명시하게 한다.
4. 새 결론이 나오면 결론 이력에 추가된다. 이전 결론은 지워지지 않고 F10 대조 대상으로 남는다.
5. 긴 토론은 라운드 요약을 계층적으로 압축해 컨텍스트를 관리한다(전체 전문은 SQLite에, 프롬프트에는 요약 + 최근 N라운드 전문).

미러피시 심층 토론의 재개는 미러피시 프로젝트를 다시 만들되, 시드 문서에 이전 리포트 요약과 새 자료를 넣는 방식이다. 미러피시가 프로젝트 이어가기를 지원하는지는 사전 실험에서 확인한다(`docs/MIROFISH_EXPERIMENT_GUIDE.md`).

### 5.5 인격의 일관성을 만드는 세 겹

1. **정의**: 페르소나 시스템 프롬프트(투자 철학, 시간 지평, 즐겨 보는 지표, 말투). 사용자 편집 가능, 버전 관리.
2. **기억(RAG, 개인 코퍼스)**: 그 페르소나가 이 종목·업종에 대해 과거에 한 발언과 그 적중 여부를 검색해 넣는다. "지난달 당신은 X라고 했고 결과는 Y였다"가 프롬프트에 들어간다.
3. **성적(F10)**: 페르소나×모델 적중률이 사회자의 종합 가중치에 반영된다.

## 6. 흐름 요약

```
종목 선택
  → 개요(구조화) + 전망 요약(LLM 1회, 캐시)                      ── 토론 없음
사용자가 테마 선택 (매수 / 매도 / 산업 동향)
  → 빠른 토론: RAG(asOf=now, 테마별 질의) → 페르소나 병렬 발언 ×N → 사회자 → Verdict
  → 심층 토론: 시드 문서 조립 → 미러피시 → 리포트 → 구조화 → Verdict
  → DebateSession에 라운드·결론·자료 스냅샷 기록 (이벤트 로그, 동기화 대상)
나중에 "재개"
  → 이전 요약 + 이후 새 자료 → "무엇이 달라졌나" → 새 Verdict 추가
F10: 모든 Verdict를 1/5/20일 뒤 실제 수익률과 대조
```

## 7. 구현 위치

`engine.debate` 아래 `DebateSession`(도메인은 `core.debate`), `DebateOrchestrator`(테마별 진행), `PersonaSnapshot`, `QuickDebateEngine`, `MiroFishDebateEngine`(`SimulationPort` 사용), `VerdictExtractor`. 발언 병렬 호출은 `LlmPort`의 `PERSONA_TURN`, 종합은 `DEBATE_MODERATOR`, 변환은 `STRUCTURED_EXTRACTION`(`docs/LLM_ROUTING.md`).

## 8. 실시간 시세·차트 (F1·F3 보강)

차트와 가격은 토스 앱처럼 스스로 움직인다.

- **데이터 경로**: 데몬이 토스 WebSocket `trade:{kr|us}`, `orderbook:{kr|us}`를 구독(계정당 연결 2개 제한 — 시세용 1개, `personal:order`용 1개). 화면에 보이는 종목 + 보유 종목 + 급등 감시 후보를 구독 100건 한도 안에서 우선순위로 관리한다.
- **분봉 집계**: 체결 스트림을 데몬이 1분봉으로 집계해 "진행 중인 봉"을 로컬 WebSocket으로 밀어 준다. 화면은 Lightweight Charts `update()`로 마지막 봉만 갱신하고, 봉이 닫히면 새 봉을 붙인다. 과거 봉은 REST `candles`로 채운다.
- **가격 영역**: 현재가·호가는 틱마다 갱신하되 화면 반영은 초당 4회로 묶는다(rAF 배치). 변동 방향에 따라 숫자 배경이 잠깐 빨강/파랑으로 깜빡인다.
- **끊김 처리**: WebSocket이 끊기면 REST 폴링(가격 1초, 호가 2초)으로 내려가고 "지연" 표시. 재연결 시 마지막 캔들을 REST로 재동기화한다. 시세 채널은 유실 가능(LOSSY)이므로 봉 집계는 REST로 주기적으로 보정한다.
- **미국 장**: 프리·정규·애프터 세션 구분을 차트 배경 띠로 표시.
