## 1. 결론 요약

- 상단 바 2행의 **사용자 이름**을 누르면 드롭다운 메뉴가 열린다: **자산 조회 · 회원정보 변경 · 알림 설정 · 로그아웃**.
- "자산 조회"를 고르면 금융결제원 인터페이스를 거쳐 **본인의 모든 자산**(은행·증권·카드·보험·대출 등 기관별 계좌와 잔액)을 **자산 모달**에 보인다. 처음이면 금융결제원 동의 화면(OAuth)으로 가서 **사용자 토큰**(개인 키, D17)을 받고, 이후에는 토큰 유효기간 안에서 조회한다.
- 자산은 **본인만** 본다(절대 규칙 8). 계좌번호는 끝 4자리만, 로그·이벤트에 남기지 않는다. 자산 데이터는 동기화하지 않는다(PROJECT 6장 "동기화 안 함").
- 이 모달은 정보 표시다. 주문·자동화와 무관하고, 토스 계좌 잔고는 여전히 토스 API가 원천이다(모달에서는 참고로 함께 보인다).

## 2. 사용자 메뉴 (드롭다운)

| 항목 | 동작 |
|---|---|
| 자산 조회 | 자산 모달 열기(3장). 토큰이 없거나 만료면 동의 흐름(4장) 먼저 |
| 회원정보 변경 | 기본·로그인 수단·연결 키·보안 네 탭. 본인 토스 키 교체도 여기(KEY_MANAGEMENT 4장의 유일한 개인 교체 경로). 상세 [ACCOUNT_SETTINGS_DESIGN.md](ACCOUNT_SETTINGS_DESIGN.md) 3장 |
| 알림 설정 | 채널(앱 안·macOS·Slack) × 항목 표, 야간 방해 금지, Slack 수량·금액 포함. 상세 [ACCOUNT_SETTINGS_DESIGN.md](ACCOUNT_SETTINGS_DESIGN.md) 4장 |
| 로그아웃 | 세션 종료. 자동화는 데몬이 계속 돈다(KEY_MANAGEMENT 5장의 옵션을 켠 구성원은 재로그인 전까지 자동화 정지) |

- 열기: 사용자 이름 클릭. 닫기: 바깥 클릭·Esc·같은 곳 클릭. 메뉴는 2행 오른쪽 끝에 붙는 팝오버(종목 검색 팝오버와 같은 틀).
- admin에게는 "회원 관리 · 공유 키 관리" 항목이 더 보인다(KEY_MANAGEMENT 4장, 구성원에게는 안 보임).

## 3. 자산 모달

주문·연기금 모달과 같은 틀(바깥 흐림 없음, 강조색 발광, 제목 바 드래그). 폭 760.

- **제목 바**: "내 자산 · {이름}" · 출처와 조회 시각("금융결제원 · 09/25 08:12 조회") · 동의 상태 칩("동의 유효 · 만료 2027-03") · 새로고침 · ✕.
- **요약 3칸**: 총자산(원화 환산) · 현금성(예금·CMA·예수금) · 투자(증권·펀드·보험 해약환급금 제외 여부 표기). 외화 자산은 조회 시점 환율로 환산하고 원 통화도 병기.
- **기관별 표**: 기관 · 계좌(끝 4자리·별칭) · 종류(입출금·예적금·증권·펀드·카드·보험·대출) · 잔액 · 통화 · 갱신 시각. 대출·카드 미결제는 음수로 분리 표시. 토스증권 계좌는 "토스 API"라고 출처를 밝히고 같은 표에 넣는다.
- **바닥 줄**: "금융결제원 동의 범위 안의 계좌만 보입니다 · 계좌번호 끝 4자리만 표시 · 이 화면의 데이터는 저장·동기화하지 않습니다 · 동의 철회는 회원정보 변경에서".
- 갱신: 모달을 열 때 조회(토큰 유효 시). 캐시는 메모리에만, 앱을 닫으면 사라진다. 새로고침은 1분 간격 제한. 금융결제원 한도는 [확인 필요].

## 4. 동의 흐름 (처음 또는 만료 시)

1. "자산 조회" 클릭 → 토큰 없음/만료 감지 → 안내 카드("금융결제원 계좌통합 동의가 필요합니다. 브라우저에서 동의 화면이 열립니다").
2. 데몬이 금융결제원 인가 URL을 만들어 **기본 브라우저**로 연다(앱 안 웹뷰 없음 — F12와 같은 원칙). 리다이렉트는 데몬의 `127.0.0.1` 콜백.
3. 콜백으로 받은 코드를 토큰으로 교환해 Keychain `stockholm/user/{userId}/kftc-token`에 넣는다. 화면에는 토큰 값이 절대 나오지 않는다.
4. 모달로 돌아와 조회한다. 실패하면 사유(동의 취소·타임아웃)만 보인다.
5. 만료 30일 전 알림 센터에 "재동의 필요".

앱 자격(client id/secret)은 admin 공유 키, 사용자 토큰은 개인 키(KEY_MANAGEMENT 2장). admin은 구성원의 토큰을 삭제할 수만 있다.

## 5. 포트와 저장

```java
public interface AssetPort {                                   // core.port (기존)
  List<ExternalAsset> assets(UserId u);                        // 토큰 없으면 ConsentRequired 예외
}
public record ExternalAsset(String institution, String maskedAccount, AssetKind kind, Money balance, Instant asOf) {}
public enum AssetKind { DEPOSIT, SAVINGS, SECURITIES, FUND, CARD, INSURANCE, LOAN, OTHER }
public interface IdentityPort { IdentityProof verify(UserId u, IdentityRequest r); }   // 본인인증(기존)
```

- 어댑터 `engine.asset.KftcAssetAdapter`: 인가 URL 생성, 콜백, 토큰 교환·갱신, 계좌 목록·잔액 조회, 도메인 변환. 응답 원문 비로깅.
- 저장: **하지 않는다.** 토큰만 Keychain. 조회 결과는 세션 메모리. 감사 로그에는 "자산 조회 실행(사용자·시각)"만.

## 6. 예외

| 상황 | 동작 |
|---|---|
| 앱 자격 없음(admin 미등록) | 메뉴 항목은 보이되 "admin이 금융결제원 앱 자격을 등록해야 합니다" |
| 토큰 없음/만료 | 동의 흐름 |
| 조회 실패 | 캐시(있으면) + 실패 시각, 알림 없음 |
| 다른 사용자 데이터 | 없다. 포트가 `userId`로만 조회하고 admin 예외 없음 |

## 7. 열린 항목 [확인 필요, 구현 시]

1. 금융결제원 API 종류(오픈뱅킹 계좌통합조회 vs 마이데이터)와 "모든 자산"의 실제 범위(은행 외 증권·카드·보험 포함 여부), 테스트베드/운영 키.
2. 토큰 유효기간·갱신 방식, 조회 한도.
3. 외화 계좌 환산 환율 출처(토스 환율 API).
