# 최초 구동과 시작 종목 (F19)

작성: 2026-09-25 / 상태: **[확정 2026-09-25]** (토스 키 "나중에"+조회 제한 모드, 로그인 모달 바깥 흐림, TOTP 포함, 시작 종목 = 평가금액 최대 보유 → 기본 종목 삼성전자/엔비디아. 남은 것은 토스 API 필드 [확인 필요]뿐) — 사용자가 준 6단계(admin 비밀번호 → 공유 키 → 토스 키 안내 → 검증 후 메인 → 시작 종목 규칙 → 직전 종목)를 화면과 로직으로 푼 것. 결정 대기 항목은 9장 / 관련: `PROJECT.md` 5장·D17·D18·F19·11.3, `docs/KEY_MANAGEMENT.md` 3장(마법사 원안)·5장(저장), `docs/LLM_ROUTING.md` 4장(프리셋), `docs/CORE_DOMAIN.md`, 화면 설계 아티팩트 "최초 구동 마법사"

## 1. 결론 요약

- 설치 후 첫 실행은 **마법사 네 단계**다: ① admin 비밀번호(+TOTP) → ② 공유 API 키 등록·검증 → ③ 토스증권 키 안내("등록하시겠습니까?") → ④ 연결 확인 → 메인 화면. 끝내기 전에는 다른 화면으로 갈 수 없고, 중간에 꺼도 **끝낸 단계부터 다시 시작**한다.
- **키는 검증에 성공한 것만 Keychain에 저장**한다. 검증은 읽기 전용 호출 한 번이며 **주문 API는 절대 부르지 않는다.** 값은 화면·로그·응답 어디에도 다시 나오지 않는다(쓰기 전용).
- ③에서 토스 키를 **건너뛸 수 있다.** 건너뛰면 메인은 열리되 "조회 제한 모드"(시세·계좌·주문 없음, 상단 배너)이고, 3번 영역의 매수·매도 버튼을 누르면 같은 안내가 다시 뜬다. **확정(2026-09-25)**. D17·KEY_MANAGEMENT는 "안내하되 건너뛸 수 있음"으로 고쳤다.
- 마법사가 끝난 뒤 매 실행·로그아웃 뒤에는 **로그인 모달**이 메인 위에 뜨고, 모든 모달 중 유일하게 **바깥을 흐린다**(3.6, 확정 2026-09-25).
- **시작 종목 규칙(로그인 직후 네 영역에 띄울 종목)**: ⑴ 이 사용자가 직전에 보던 종목 → ⑵ 보유 종목 중 **평가금액(현재가 × 수량, 원화 환산)이 가장 큰 종목** → ⑶ 코드 상수 **기본 종목: 국내 삼성전자 `005930`, 미국 엔비디아 `NVDA`**(사용자 설정 "기본 시장"으로 고르며 기본값 국내). 시가총액 1위 조회는 두지 않는다. 위에서부터 처음 성립하는 것을 쓰고, 각 단계의 실패(키 없음·API 실패·상장폐지)는 다음 단계로 넘어간다.
- 직전 종목은 **사용자별 설정** `lastViewedStock`으로 저장하고 동기화한다(같은 사용자의 다른 디바이스에서도 이어 본다).

## 2. 상태 기계 (설치 단위)

설치(데몬 하나)는 `SetupState` 하나를 갖는다. SQLite `installation` 테이블 한 행. 마법사 화면은 이 상태만 보고 어느 단계를 띄울지 정한다.

```
NOT_STARTED ─①→ ADMIN_CREATED ─②→ SHARED_KEYS_DONE ─③→ TOSS_DECIDED ─④→ COMPLETE
```

| 상태 | 뜻 | 다음으로 가는 조건 |
|---|---|---|
| `NOT_STARTED` | 설치 직후. 사용자 없음 | admin 계정 생성(비밀번호 + TOTP 등록 완료) |
| `ADMIN_CREATED` | admin은 있으나 공유 키 없음 | LLM 제공자 1개 이상 + DART 키가 검증·저장됨 |
| `SHARED_KEYS_DONE` | 필수 공유 키 있음 | 토스 키를 검증·저장했거나 "나중에"를 골랐음(선택 기록) |
| `TOSS_DECIDED` | 토스 결정 끝 | 연결 확인 화면에서 모든 등록 키의 상태가 표시되고 사용자가 "시작"을 누름 |
| `COMPLETE` | 정상 운영 | — (이후 마법사는 다시 뜨지 않음. 키 변경은 설정 화면) |

- 상태 전이는 데몬만 한다(`POST /setup/...`). 화면은 `GET /setup/state`로 현재 상태와 단계별 진행 정보(등록된 키 종류·검증 시각·끝 4자리)를 받는다.
- **`COMPLETE` 전에는 `/setup/*`와 헬스 외 모든 로컬 API가 403이다**(KEY_MANAGEMENT 8장 테스트). 로그인·주문·시세·토론 어느 것도 열리지 않는다.
- 앱을 중간에 끄면 다음 실행 때 같은 상태에서 이어진다. 비밀번호를 만들어 두고 껐으면 ②부터, 키를 넣다 껐으면 저장된 키는 남고 ②의 목록에 "검증됨"으로 표시된다.
- 마법사 중에는 아직 세션이 없으므로 `/setup/*`는 **로컬 토큰**(데몬이 기동 시 만든 파일, Electron만 읽음)으로만 보호한다. ① 뒤에는 방금 만든 admin 비밀번호로 짧은 마법사 세션을 만들어 ②~④에 붙인다(다른 프로세스가 `/setup/keys`를 부르지 못하게).

## 3. 화면 (마법사)

전체 화면 하나에 왼쪽 단계 표시(①②③④), 오른쪽 카드. 상단 바·서랍·하단 상태줄은 없다. 창을 닫으면 앱이 종료된다(트레이 상주 없음, 마법사 중에는 데몬이 할 일이 없다).

### 3.1 ① admin 비밀번호

| 요소 | 규칙 |
|---|---|
| 표시 이름 | 1~20자. 상단 바 2행에 보이는 이름. 기본값 "admin" |
| 비밀번호 · 확인 | 12자 이상, 두 칸 일치. 강도 표시(길이·문자 종류). 흔한 비밀번호 목록 거부. 저장은 Argon2id |
| TOTP 등록 | QR(otpauth URI) + 수동 키 표시 → 앱에서 만든 6자리 입력으로 확인. 복구 코드 8개를 한 번 보여 주고 "저장했습니다" 확인 |
| 안내 | "이 계정이 이 설치의 admin이 됩니다. 구성원 초대·공유 키 관리는 admin만 할 수 있습니다." |

- 사용자 요청은 "비밀번호 입력 및 확인"까지다. **TOTP를 같은 단계에 넣은 것은 제안**이다(PROJECT 5장 "비밀번호 + TOTP 기본"). 단독 모드에서 TOTP를 나중으로 미루려면 5장을 고쳐야 한다(9장 2).
- 이 단계에서 디바이스 키쌍도 만든다(Keychain `stockholm/device/private-key`). 화면에는 보이지 않는다.

**TOTP 구현** [확정 2026-09-25, 포함]. TOTP는 RFC 6238(HMAC-SHA1 + 30초 시간 카운터, 6자리)이라 Google Authenticator·Microsoft Authenticator·1Password·Apple 암호 앱 어느 것이든 쓸 수 있다.
- 코드 생성·검증은 `javax.crypto`만으로 100줄 안에 구현한다. 외부 라이브러리 없음, GraalVM 네이티브에 문제 없음. `engine.auth`에 두고 `Clock`을 주입받아 고정 시계로 테스트한다. 허용 오차는 앞뒤 1구간(±30초), 같은 코드는 한 번만 받는다(재사용 거부).
- 시드(base32 20바이트)는 Keychain `stockholm/user/{userId}/totp-seed`에만 둔다. QR(`otpauth://totp/Stockholm:{이름}?secret=…&issuer=Stockholm`)은 **데몬이 이미지로 만들어** 보내고, 렌더러는 시드 문자열을 받지 않는다. "수동 키 보기"를 눌러야 시드를 한 번 보여 주며 등록이 끝나면 다시 볼 수 없다.
- QR 이미지 생성은 ZXing core(Apache-2.0, 순수 Java, 리플렉션 없음) 후보. 새 의존성이므로 1단계 착수 때 확정한다 [제안]. 대안은 QR 인코더를 직접 쓰는 것(약 300줄).
- 복구 코드 8개는 Argon2id 해시로 저장하고 1회용. 휴대폰 분실 시 복구 코드로 로그인 → TOTP 재등록.
- 로그인 화면(3.6)과 step-up(주문 승인·가드레일 변경·lease 강제 인수·키 변경)이 같은 검증 함수를 쓴다.

### 3.2 ② 공유 API 키 등록

카드 하나에 키 종류가 **그룹별 목록**으로 나온다. 각 행: 이름 · 필수/선택 칩 · 입력 칸(마스킹) · "검증" 버튼 · 상태 칩(미등록 / 검증 중 / 검증됨 ···끝4자리 / 실패: 사유).

| 그룹 | 항목 | 필수 |
|---|---|---|
| LLM | OpenAI 키 · Claude 키 · DeepSeek 키 · Ollama 주소(기본 `http://127.0.0.1:11434`) | **1개 이상** |
| 공시 | DART 인증키 | **필수** |
| 시장 데이터 | KRX Open API 인증키 · Massive 키 | 선택 |
| 뉴스·커뮤니티 | 네이버 검색 client id/secret | 선택 |
| 공공 | 공공데이터포털 서비스 키 · SEC EDGAR 연락처 이메일(키 아님, User-Agent용) | 선택 |
| 알림 | Slack 봇 토큰 | 선택 |
| 금융결제원 | 앱 자격 client id/secret | 선택 |

- "다음" 버튼은 **LLM 1개 이상 + DART가 검증됨일 때만** 활성. 선택 항목은 비워 두고 넘어가면 설정 > 키 관리에서 admin이 나중에 넣는다.
- 검증 방법은 5장 표. 실패한 값은 저장하지 않고 입력 칸에 그대로 남긴다(다시 고칠 수 있게). 성공하면 입력 칸은 비워지고 상태 칩만 남는다(값은 되돌려 주지 않음).
- LLM이 하나라도 검증되면 카드 아래에 **LLM 프리셋** 선택(균형 · 품질 우선 · 비용 최소 · 로컬 전용, 기본 균형)이 나타난다. 등록된 제공자만으로 경로가 짜인다(LLM_ROUTING 4장). 여기서 고르지 않으면 균형.
- 붙여넣기 뒤 자동 검증은 하지 않는다(잘못 붙인 값이 외부로 나가지 않게). "검증"을 눌러야 나간다.

### 3.3 ③ 토스증권 키 안내

> **거래를 시작하려면 토스증권 Open API 인증키가 필요합니다.**
> 시세·계좌·주문은 모두 이 키로 합니다. 키는 본인 계좌에만 쓰이고 admin을 포함해 누구도 값을 다시 볼 수 없습니다.
> 토스증권 앱 > Open API에서 client_id와 client_secret을 발급받고, 이 Mac의 공인 IP(`xxx.xxx.xxx.xxx`)를 허용 IP에 등록하세요.
> API 인증키를 등록하시겠습니까?  [지금 등록]  [나중에]

- **지금 등록** → 같은 카드가 입력 폼으로 바뀐다: client_id · client_secret · "검증" → 성공 시 **계좌 선택**(종합매매 계좌 목록, 여러 개면 `accountSeq` 라디오, 계좌번호는 끝 4자리) → "다음".
- **나중에** → 선택을 기록하고 ④로. 메인은 조회 제한 모드로 열린다(4장). 경고 문구: "토스 키가 없으면 시세·차트·계좌·주문이 모두 꺼진 채로 열립니다."
- 공인 IP는 데몬이 조회해 보여 준다(허용 IP 사전 등록 제약 때문에 이 단계에서 가장 많이 막힌다). 403이면 "허용 IP 미등록으로 보입니다. 위 IP를 등록한 뒤 다시 검증하세요."
- admin의 토스 키는 **공용 시세 수집에도 쓰인다**(D17). 따라서 admin이 건너뛰면 구성원에게도 시세가 없다. 안내에 이 사실을 한 줄 더 넣는다.

### 3.4 ④ 연결 확인

등록한 모든 키를 한 번 더 실제로 호출해 표로 보여 준다: 항목 · 상태(정상 / 실패: 사유 / 미등록) · 응답 시간 · 확인 시각. 토스는 계좌 이름·끝 4자리와 "매수 가능 금액 조회 정상"까지.

- 모두 정상이거나 실패가 선택 항목뿐이면 **"Stockholm 시작"** 버튼 활성. 필수 항목이 실패면 해당 단계로 돌아가는 링크.
- "시작"을 누르면 `COMPLETE`로 바뀌고, 데몬이 **종목 마스터 첫 동기화**(토스 키가 있을 때)와 **시작 종목 결정**(6장)을 한 뒤 메인 화면으로 넘어간다. 마스터 동기화가 길면(수십 초) 진행 표시를 카드 안에 보여 준다.
- 이 화면은 이후 설정 > 키 관리의 "연결 상태" 탭과 같은 컴포넌트다(한 번 만들어 두 곳에서 쓴다).

### 3.5 구성원의 첫 로그인 (참고)

로그인 화면 "구성원 등록" → 등록 코드 → 비밀번호 + TOTP → **③과 같은 토스 키 안내**(공유 키 단계 없음) → ④ 대신 본인 토스 연결 확인만 → 메인. 구성원도 "나중에"를 고를 수 있고 그러면 본인 계좌·주문만 꺼진다(공용 시세는 admin 키로 계속 온다).

### 3.6 로그인 모달 (매 실행) [확정 2026-09-25]

마법사가 끝난 설치에서는 앱을 켤 때마다, 그리고 로그아웃 뒤에 **메인 위에 로그인 모달**이 뜬다. **모든 모달 중 유일하게 바깥 화면을 흐리게(blur) 한다.** 주문·정정·연기금·자산 모달은 바깥을 흐리지 않는다(F1).

| 요소 | 규칙 |
|---|---|
| 사용자 선택 | 이 설치의 계정(최대 4) 중 하나. 마지막 로그인 사용자가 기본 선택 |
| 비밀번호 · TOTP | 비밀번호 → TOTP 6자리. 5회 실패 시 잠금 15분(PROJECT 5장 "시도 제한과 잠금") |
| 링크 | 구성원 등록(등록 코드) · 복구 코드로 로그인 |
| 바닥 줄 | 데몬 연결 상태 · 버전. 데몬이 아직 안 떴으면 "데몬 기동 중" 스피너 |
| 바깥 | 로그인 전 빈 메인(네 영역 빈 상태, 데이터 없음)을 6px 흐림 + 옅은 덮개. 클릭·키 입력 막힘. Esc로 닫히지 않음 |

- **흐림은 연출이지 보안 수단이 아니다.** 로그아웃 시 화면 상태(종목·보유·토론)를 먼저 비우고 나서 모달을 띄운다. 흐려진 배경에 직전 사용자의 숫자가 남아 있으면 안 된다(테스트 10장).
- 로그인이 끝나면 흐림이 걷히면서 시작 종목 결정(6장) 결과로 네 영역이 채워진다. 결정이 2초를 넘기면 흐림을 먼저 걷고 빈 영역에 진행 표시를 보인다.
- 원격 모드(7단계)의 로그인 화면도 같은 모달을 쓴다(디바이스 인증 추가).

|---|---|---|---|

- 검증 호출은 각 어댑터의 `verifyCredential()`이 한다. 어댑터가 자기 API의 가장 가벼운 읽기 호출을 고르고, 결과를 `CredentialCheck(OK | REJECTED(사유) | UNREACHABLE)`로 돌려준다. 마법사는 이 타입만 본다.
- 실패 사유는 사용자가 고칠 수 있는 말로 바꾼다: 401·403 → "키가 틀렸거나 허용 IP가 아닙니다", 429 → "호출 한도 초과, 잠시 뒤 다시", 연결 실패 → "네트워크 또는 주소 확인".
- 값이 저장되기 전까지는 메모리에만 있고, 검증 요청 하나가 끝나면 지운다. 감사 로그에는 "키 검증 시도(종류·결과·시각)"만.
- 검증은 마법사에서만 아니라 설정 > 키 관리의 "재검증"과 하루 1회 정기 확인(KEY_MANAGEMENT 6장)에서도 같은 함수를 쓴다.

## 6. 시작 종목 규칙

로그인이 끝나 메인을 그릴 때 데몬이 `StartStockResolver`로 종목 하나를 정한다. **순수 규칙은 `core`에, 조회는 포트로.**

```java
public interface StartStockResolver {                          // core.trading
  StartStock resolve(UserId user);                             // 항상 값을 돌려줌(마지막 후보는 상수)
}
public record StartStock(StockCode code, StartStockReason reason) {}
public enum StartStockReason { LAST_VIEWED, LARGEST_POSITION, DEFAULT }
```

| 순서 | 후보 | 조건 | 실패 시 |
|---|---|---|---|
| ⑴ | `lastViewedStock`(사용자 설정) | 값이 있고 종목 마스터에 있으며 상장폐지 아님 | ⑵ |
| ⑵ | 보유 종목 중 **평가금액(현재가 × 수량) 원화 환산이 가장 큰 종목** | 본인 토스 키 있음, 보유 조회 성공, 보유 1개 이상 | ⑶ |
| ⑶ | `DEFAULT_START_STOCK_KR` = 삼성전자 `005930` / `DEFAULT_START_STOCK_US` = 엔비디아 `NVDA`, 설정 "기본 시장"(기본값 국내)으로 선택 | 항상 | — |

- **"가장 많은 자산이 투입된"의 정의 = 평가금액(보유 수량 × 현재가)의 원화 환산** [확정 2026-09-25]. 토스 보유 조회가 주는 평가금액·원화 환산값을 그대로 쓴다 [확인 필요: 필드명]. 그 값이 없으면 수량 × 마지막 현재가(시세 캐시) × 현재 환율(`MarketDataPort.exchangeRate`)로 계산한다. 같으면 매입 원가가 큰 쪽, 그래도 같으면 종목 코드 순. 장 마감 중에는 마지막 종가 기준이라 하루 안에서는 값이 바뀌지 않는다.
- **기본 종목은 상수 두 개** [확정 2026-09-25]: 국내 삼성전자 `005930`, 미국 엔비디아 `NVDA`. 어느 것을 쓸지는 사용자 설정 "기본 시장"(국내/미국, 기본값 국내, 동기화)이 정한다. 시가총액 1위를 조회해 정하는 방식은 출처가 불확실해 두지 않는다. 상장폐지·종목 코드 변경이 생기면 릴리스에서 상수를 바꾼다.
- ⑴은 **사용자별**이고 ⑵도 본인 키·본인 계좌라 사용자별이다. ⑶은 사용자 설정 하나로 정해지는 상수.
- 결정 결과와 사유(`reason`)를 화면에 넘겨 첫 진입 때만 작은 토스트로 알린다: "보유 중 평가금액이 가장 큰 종목을 열었습니다" / "직전에 보던 종목입니다". 기본 종목일 때는 토스트 없음.
- 어느 단계든 **외부 조회는 2초 안에 답이 없으면 그 후보를 포기**하고 다음으로 간다. 시작 화면이 API 지연에 묶이지 않게 한다. 포기한 뒤 늦게 온 응답은 버린다.

### 6.1 직전 종목 저장

- 사용자 설정 `lastViewedStock = {code, market, viewedAt}`. 네 영역의 종목이 바뀔 때마다 갱신하되 **2초 디바운스**(검색 팝오버에서 빠르게 옮겨 다닐 때 이벤트 남발 방지). 서랍·모달에서 잠깐 미리 보는 것은 "보던 종목"이 아니므로 네 영역 전환만 센다.
- 설정 이벤트 로그로 저장되어 동기화된다(6장 "동기화함: 설정"). 다른 디바이스에서 로그인해도 이어진다.
- 로그아웃·앱 종료 시에는 별도 저장이 없다(이미 디바운스로 저장됨). 강제 종료로 마지막 2초가 날아가도 직전 값이 남는다.

### 6.2 시퀀스

```
Electron 기동 → 데몬 기동 대기 → GET /setup/state
  ├ COMPLETE 아님 → 마법사(해당 단계)
  └ COMPLETE → 로그인 모달(바깥 흐림, 3.6) → POST /session (사용자 + 비밀번호 + TOTP)
        → GET /session/start-stock  (데몬: StartStockResolver, 2초 상한)
        → 메인 화면(네 영역 = 시작 종목) → 토스트(사유)
```

## 7. 포트와 저장

- 새 포트: `CredentialVerifier`(어댑터마다 구현, `core.port`에 인터페이스 `CredentialCheck verify(SecretValue)`). 시가총액 조회 포트는 두지 않는다(기본 종목이 상수).
- 기존 포트 사용: `SecretStorePort`(저장), `TradingPort.snapshot`(보유), `MarketDataPort.exchangeRate`, `UserSettingsPort`(lastViewedStock), `Clock`.
- 저장: `installation(setup_state, created_at, admin_user_id)`, `credential_meta(kind, scope[shared|user], user_id?, last4, verified_at, status)`, 사용자 설정 이벤트 `UserSettingChanged(lastViewedStock)`(CORE_DOMAIN 9장 이름과 통일). 표 정의는 `docs/DB_SCHEMA.md` 4·5장. 키 값은 Keychain만(KEY_MANAGEMENT 5장).
- Flyway: V1에 `installation`·`credential_meta`가 들어간다(1단계 리포 골격 범위).

## 10. 테스트

- `SetupState` 전이: 각 상태에서 허용된 전이만 되는지, `COMPLETE` 전 다른 API 403, `COMPLETE` 후 `/setup/*` 404.
- 필수 키 없이 ②를 못 넘는지, 검증 실패 값이 `SecretStorePort`(메모리 fake)에 없는지, 성공 값이 응답·로그·감사 로그에 없는지(표식 값 검색).
- `CredentialVerifier` 어댑터: WireMock으로 200/401/403/429/타임아웃 각각 `CredentialCheck` 매핑. **토스 검증이 주문 엔드포인트를 절대 부르지 않는지**(WireMock에 주문 경로를 두고 호출 0회 검증).
- `StartStockResolver`(fake 포트): ⑴~⑶ 각 경로, 상장폐지 종목의 ⑴ 건너뜀, 평가금액 동률 시 매입 원가 비교, 미국 보유의 환산, 2초 타임아웃 시 다음 후보, 토스 키 없음 → ⑶, 기본 시장 설정 국내/미국에 따라 005930/NVDA.
- TOTP: RFC 6238 부록 B 테스트 벡터(SHA-1, 30초, 6자리)로 코드 생성 검증, 고정 `Clock`으로 ±1 구간 허용과 같은 코드 재사용 거부, 5회 실패 잠금 15분, 복구 코드 1회성.
- `lastViewedStock` 디바운스: 2초 안 여러 번 전환 시 마지막 값 한 번만 저장(고정 `Clock`).
- 구성원 첫 로그인: 공유 키 단계가 없고 본인 토스 키만 묻는지, 구성원이 `/setup/keys`를 부르면 403인지.
- 로그인 모달(프론트): 로그아웃 직후 모달 뒤 DOM에 직전 사용자의 종목·보유·토론 텍스트가 없는지, 흐림 상태에서 바깥 클릭·키 입력이 막히는지, Esc로 닫히지 않는지, 데몬 미기동 시 "기동 중" 표시.
