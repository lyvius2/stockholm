## 1. 결론 요약

- admin 전용 모달 "LLM 경로"(폭 760, step-up 5분). **카테고리 카드 다섯 장**이 화면의 전부다: **토론 · 리포트·요약 · 거래 판단 · 추천 · 번역**. 카드마다 **주 LLM(제공자 ▾ + 모델 ▾)** 하나와 **대체 LLM** 하나(선택)를 고른다. 임베딩은 카드 아래 한 줄(로컬 Ollama 고정 표시).
- **키가 등록·검증된 제공자만** 고를 수 있다. 미등록은 목록에서 회색 "키 미등록"이며 고를 수 없다.
- 카테고리 하나가 목적(`LlmPurpose`) 여러 개를 덮는다(2장 표). 코드는 여전히 목적 단위로 라우팅하고, 화면의 카테고리 선택을 목적별 경로로 **펼쳐서 저장**한다.
- **프리셋**(균형 · 품질 우선 · 비용 최소 · 로컬 전용)은 다섯 카드를 한 번에 채운다. **"고급"** 토글을 켜면 카드 안에 목적별 행(예: 토론 카드 안의 페르소나 발언 · 사회자 · 개입 응답 · 결론 구조화)이 펼쳐져 따로 바꿀 수 있다. 기본은 닫힘.
- 거래 판단 카드의 실패 시 정책은 고정이다: 자동 매도 판단 → **판단 보류**, 급등 재료 확인 → **매수 안 함**. 화면은 표시만 한다.

## 2. 카테고리와 목적 대응 (코드 한곳의 표)

| 카테고리 | 포함 목적 | 화면 설명 한 줄 | 개인 데이터 |
|---|---|---|---|
| **토론** | `PERSONA_TURN` · `DEBATE_MODERATOR` · `USER_CHAT` · `STRUCTURED_EXTRACTION` | 페르소나 발언, 사회자 결론, 토론 중 질문·개입 응답, 결론 구조화 | 매도 토론에 보유 수량 포함 가능 🔒 |
| **리포트·요약** | `MARKET_REPORT` · `DOCUMENT_DIGEST` · `RETROSPECTIVE` | 일간·주간 리포트, 개요·전망·업종 요약, 공시 분류, 회고 | 리포트 개인 절·회고 🔒 |
| **거래 판단** | `SELL_DECISION` · `SURGE_CATALYST_CHECK` | 자동 매도 판단, 급등 재료 확인. 실패 시 판단 보류 · 매수 안 함(고정) | 보유 단가·수량 🔒 |
| **추천** | `RECOMMENDATION_ANALYSIS` | F5 유력 종목 2단 분석·약식 토론 | 없음 |
| **번역** | `TRANSLATE` | 영→한 번역(커뮤니티·미국 뉴스) | 없음 |
| 임베딩 | `EmbeddingPort` | RAG 색인·검색. 로컬 Ollama `bge-m3` 고정, 바꾸면 재색인 | 원문(로컬) |

- 카테고리 선택은 포함 목적 전부에 같은 (제공자, 모델)을 준다. 목적별 기본 파라미터(temperature·최대 토큰·타임아웃)는 코드 기본값을 쓴다.
- "고급"에서 목적별로 바꾼 값이 있으면 그 목적만 카테고리 값보다 우선한다. 카드에는 "고급 설정 2건"이라고 표시된다.
- 프리셋의 카테고리별 기본은 LLM_ROUTING 4장 표를 카테고리 단위로 묶은 것: 균형 = 토론 Claude / 리포트·요약 Ollama / 거래 판단 OpenAI(없으면 Claude) / 추천 DeepSeek(없으면 Ollama) / 번역 Ollama. 등록되지 않은 제공자는 다음 후보로 내려간다.

## 3. 화면 구성

**제목 바**: "🧭 LLM 경로 · admin" · 프리셋 칩(균형 · 품질 우선 · 비용 최소 · 로컬 전용 · 사용자 정의) · 고급 토글 · step-up 남은 시간 · ✕

| 주 LLM | 제공자 ▾ · 모델 ▾ (등록 제공자만 활성) |

**임베딩 줄**: Ollama `bge-m3` · 1024차원 · "바꾸면 전체 재색인(N문서, 예상 시간)" · 고급에서만 변경.

**바닥 줄**: [프리셋으로 되돌리기] · [검증] · [저장] · 마지막 저장(시각·누가) · 예산 요약(설치 일일 · 오늘 · 예비).

## 4. 규칙

1. **선택 가능 = `credential_meta.status = VERIFIED`인 제공자**(Ollama는 주소 검증 + 모델 1개 이상). 키를 삭제하면 그 제공자가 든 카드에 경고가 뜨고, 저장된 경로에서는 실행 시 자동으로 건너뛴다(주 → 대체 → 실패 정책).
2. **저장 검증**: 다섯 카드 모두 주 LLM 있음 · 모든 선택이 VERIFIED · 주와 대체가 같은 (제공자, 모델)이 아님 · 로컬 전용 프리셋이면 클라우드 없음 · 임베딩 변경 시 재색인 확인.
3. **저장 결과**는 목적별 `llm_route` 행으로 펼쳐진다(`chain_json` = [주, 대체]). 고급 행은 그 목적만 덮어쓴다. 프리셋 이름·고급 사용 여부·구성원 허용 제공자·임베딩 모델은 `shared_setting`.
4. 🔒 카테고리는 사용자별 "개인 데이터 LLM 전송 허용"과 교차한다. 카드 툴팁에 사용자별 실제 경로("지혜: Claude 꺼짐 → Ollama")를 보여 준다.
5. 저장마다 감사 로그 + `llm_route_history`(최근 20건, 되돌리기). "이 디바이스에서만"은 고급 토글 안의 옵션(LLM_ROUTING 10장).
6. 모델 목록 = 검증 때 받은 목록 ∪ `llm_price`. 목록 밖 이름 직접 입력은 고급에서만, 테스트 호출 필수 [제안].
7. 구성원은 읽기 전용 보기(카드의 주·대체 표시, 저장 없음) [제안].

## 5. 데이터

- `llm_route(scope, purpose, persona_id, chain_json, updated_at, updated_by)` — 목적 단위(변경 없음). 카테고리는 저장 단위가 아니라 화면·프리셋의 묶음이다.
- `shared_setting`: `llm.preset`, `llm.advanced`(0/1), `llm.category.{DEBATE|REPORT|TRADE|RECOMMEND|TRANSLATE}`(카드 선택값, 고급 행과 대조용), `llm.memberAllowedProviders`, `llm.embedding.model`.
- `llm_route_history` — 4장 5번.
- 로컬 API: `GET /llm/routes`(읽기, 카테고리 뷰 + 목적별 뷰), `PUT /admin/llm/routes`(카테고리 값 + 고급 덮어쓰기 → 서버가 목적별로 펼쳐 검증·저장), `POST /admin/llm/routes/test`, `POST /admin/llm/routes/preset/{name}`.
- 카테고리 ↔ 목적 표는 `engine.llm.LlmCategory` enum 한곳.

## 6. 예외

| 상황 | 동작 |
|---|---|
| 등록 제공자 0개 | 카드 전체 비활성 + "회원 관리 › 공유 키에서 LLM 키를 먼저 등록하세요" |
| 키 삭제로 카드의 주 LLM이 미등록 | 카드 경고 + admin 알림. 실행은 대체 → 실패 정책 |
| 테스트 실패 | 사유 표시(401·429·시간 초과). 저장은 막지 않음 |
| 고급 행과 카드 값 충돌 | 고급 행이 우선. 카드에 "고급 설정 N건" 표시, 카드 값을 바꿔도 고급 행은 유지(되돌리기 버튼으로 해제) |
| 구성원 `PUT` | 403 |

## 7. 테스트

- 카테고리 값이 포함 목적 전부로 펼쳐지는지, 고급 행이 그 목적만 덮는지.
- 미등록 제공자 저장 거부, 키 삭제 후 라우터가 건너뛰는지(주 → 대체 → 정책).
- 프리셋 적용이 등록 제공자만으로 채워지는지(제공자 조합별).
- 거래 판단의 실패 정책이 화면 값과 무관하게 고정인지.
- 사용자별 개인 데이터 스위치와 교차한 실제 경로.
- 구성원 `PUT` 403, admin step-up 없이는 403, 이력 20건 보존.

## 8. 결정 (2026-09-26 확정)

1. 카테고리 다섯 개(토론 · 리포트·요약 · 거래 판단 · 추천 · 번역)와 2장의 목적 대응 그대로.
2. 구성원 읽기 전용 보기 **둔다**.
3. 고급 모드 범위 = 목적별 행 + 페르소나별 행 + 디바이스 덮어쓰기 + 모델 직접 입력(테스트 호출 필수).
