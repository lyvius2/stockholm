작성: 2026-09-25 / 상태: **[제안]** — 사용자 메뉴의 세 항목(회원정보 변경 · 알림 설정 · 회원 관리/공유 키)의 기능과 화면. 개인정보 항목은 "ID · 비밀번호 · 이름 · Slack ID" 요청을 바탕으로 보안 항목을 더한 것 / 관련: [KEY_MANAGEMENT.md](KEY_MANAGEMENT.md) 2·4·5장, [FIRST_RUN_DESIGN.md](FIRST_RUN_DESIGN.md) 3.1·3.5·5장, [ASSET_DESIGN.md](ASSET_DESIGN.md) 2장(사용자 메뉴), [LLM_ROUTING.md](LLM_ROUTING.md) 8·9장, [DB_SCHEMA.md](DB_SCHEMA.md) 4·5장, [PROJECT.md](../PROJECT.md) 5장·7장(NOTIFY)·10.1(야간 방해 금지)·D10·D12·D17, 화면 설계 아티팩트 "계정·알림·회원 관리"

## 1. 결론 요약

- 상단 바 2행 사용자 이름 → 드롭다운의 세 항목이 각각 **모달**(자산 모달과 같은 틀: 폭 760, 바깥 흐림 없음, 강조색 발광, 제목 바 드래그)로 열린다. admin에게만 "회원 관리 · 공유 키"가 보인다. **모달은 한 번에 하나**: 회원정보 모달을 보다가 자산 조회나 다른 모달을 열면 앞의 모달은 자동으로 닫힌다(저장하지 않은 입력은 사라지며, 입력 중이면 확인 창) [확정 2026-09-25].
- **개인정보는 요청하신 네 가지가 뼈대다**: 표시 이름(= 로그인 때 고르는 이름, 별도 ID 없음), 비밀번호, Slack 수신 계정, 그리고 이메일(선택). 여기에 **이미 확정된 보안 항목이 같은 화면에 있어야 한다**: TOTP 재등록·복구 코드 재발급(로그인 수단), **본인 토스 키 교체**(개인 키의 유일한 본인 교체 경로), 금융결제원 동의 철회, 개인 키 추가 암호화 옵션, 개인 데이터 LLM 전송 허용(제공자별). 이것들은 "정보"가 아니라 "내 계정의 열쇠"라 다른 화면에 둘 곳이 없다.
- **알림 설정**은 사용자별로 채널(앱 안 · macOS · Slack DM) × 항목(체결, 가드레일, 승인 요청, 킬 스위치, 토론 완료, 데이터 갱신, 리포트, 키·IP 문제, 예산)을 표로 켜고 끈다. 야간 방해 금지(긴급만 통과)와 Slack에 수량·금액을 넣을지도 여기서.
- **회원 관리 · 공유 키**는 admin 전용이고 여는 순간 step-up(TOTP)을 거친다. 탭 둘: 회원 관리(4명 등록부, 등록 코드 발급, 정지, 토스 키 삭제, 디바이스 폐기, 데이터 파기) · 공유 키(마법사 ②와 같은 목록으로 교체·삭제·재검증, 공유 설정).
- 모든 변경은 감사 로그에 남고(값은 남기지 않음), 키 값은 어디에서도 다시 보이지 않는다.

## 3. 회원정보 변경 모달

폭 760, 제목 "👤 회원정보 · {이름}". 왼쪽 세로 탭 넷: **기본 · 로그인 수단 · 연결(키) · 보안·개인정보**. 저장은 항목 단위(각 항목의 "저장"), 전체 저장 버튼은 없다(항목마다 인증 요구가 달라서).

### 3.1 기본

| 항목 | 규칙 |
|---|---|
| 표시 이름 | 1~20자, 설치 안에서 유일. 로그인 모달의 사용자 칩·상단 바·감사 로그에 쓰인다. **별도 로그인 ID를 두지 않는다**(사용자를 고르고 비밀번호를 넣는 방식이라 ID가 필요 없음) [제안] |
| 역할 | 표시만(admin / 구성원). 바꾸지 못한다 |
| 이메일 | 선택. relay를 붙인 뒤 새 디바이스 등록·계정 복구의 보조 인증에만 쓴다(PROJECT 5장). 단독 모드에서는 쓰이지 않으므로 비워 둘 수 있다 |
| Slack 수신 계정 | Slack 사용자 ID(`U0…`) 또는 표시 이름. "테스트 DM 보내기" 버튼(admin이 봇 토큰을 등록한 경우만 활성). 비밀값이 아니므로 DB(`app_user.slack_user_id`) |
| 가입일 · 마지막 로그인 · 디바이스 | 표시만 |

### 3.2 로그인 수단

- **비밀번호 변경**: 현재 비밀번호 → 새 비밀번호(12자 이상, 강도 표시, 흔한 비밀번호 거부) → 확인. 저장 시 다른 세션은 유지(단일 디바이스 전제), relay 연결 후에는 다른 디바이스 세션을 끊는다.
- **TOTP**: 상태(등록 2026-09-25) · "재등록"(현재 TOTP 6자리 확인 → 새 QR → 새 코드 확인 → 옛 시드 폐기) · "복구 코드 재발급"(남은 개수 표시, 재발급 시 옛 코드 전부 무효, 8개를 한 번만 보여 줌).
- 패스키(선택, PROJECT 5장): 등록·삭제. 1단계에서는 자리만 두고 비활성 [제안].
- 로그인 이력: 최근 10건(시각·디바이스·성공/실패). 실패 잠금 상태면 해제 시각 표시.

### 3.3 연결(키) — 본인 것만

| 항목 | 표시 | 할 수 있는 것 |
|---|---|---|
| 토스증권 키 | 상태 칩(검증됨 ···1234 · 계좌 ···1234 · 마지막 검증 시각) 또는 "미등록(조회 제한 모드)" | **교체**(TOTP 재확인 → client_id/secret 입력 → 계좌 목록 검증 → 계좌 선택 → 저장. 마법사 ③과 같은 카드) · **지금 등록**(미등록일 때). 삭제는 admin만(KEY_MANAGEMENT 4장) |
| 금융결제원 동의 | 동의 유효·만료일 또는 미동의 | **재동의**(브라우저) · **동의 철회**(토큰 삭제, 자산 조회 비활성) |
| Slack DM | 봇 토큰 등록 여부(admin) + 내 수신 계정 | 3.1로 이동 |

값은 절대 다시 보이지 않는다. 교체 성공 시 입력 칸을 비운다(FIRST_RUN 5장과 같음).

### 3.4 보안·개인정보

| 항목 | 기본 | 설명 |
|---|---|---|
| 개인 키 추가 암호화 | 꺼짐 | 켜면 내 토스 키를 내 비밀번호에서 유도한 키로 한 번 더 감싼다. **재부팅 후 내가 로그인하기 전까지 내 자동화는 멈춘다**는 경고를 확인해야 켜진다(KEY_MANAGEMENT 5장) |
| 로그아웃 시 자동화 정지 | 꺼짐 | 켜면 로그아웃하는 순간 내 자동화가 멈추고 다음 로그인 때 재개(KEY_MANAGEMENT 5장 옵션) |
| 개인 데이터 LLM 전송 허용 | Ollama 켬, OpenAI·Claude·DeepSeek 꺼짐 | 제공자별 스위치. 꺼진 제공자에는 보유 단가·수량·손익이 든 프롬프트(`SELL_DECISION`·`RETROSPECTIVE`·리포트 개인 절)가 가지 않고 폴백 정책대로 처리된다(LLM_ROUTING 8장). 각 제공자의 데이터 처리 정책 링크 |
| 내 데이터 내보내기 | — | 내 이벤트 로그·토론·설정을 JSON으로(계좌번호·키 제외) [제안, 후순위] |
| 계정 탈퇴 요청 | — | admin에게 요청 알림만 보낸다. 실제 처리는 5장 |

## 4. 알림 설정 모달

폭 760, 제목 "🔔 알림 설정 · {이름}". 사용자별 설정(`user_setting`의 `notify.*`, 동기화).

**채널 줄**: 앱 안(토스트 + 알림 센터, 항상 켬) · macOS 알림(창이 닫혀 트레이만 있을 때, 기본 켬) · Slack DM(내 수신 계정과 admin의 봇 토큰이 모두 있어야 활성. 없으면 사유 표시).

**항목 표** (행 = 알림 종류, 열 = 앱 안 / macOS / Slack / 긴급):

| 알림 | 앱 안 | macOS | Slack | 긴급(방해 금지 통과) |
|---|---|---|---|---|
| 체결·거부(F14) | 켬(고정) | 켬 | **켬** | — |
| 가드레일 발동·자동 주문 거부 | 켬(고정) | 켬 | 켬 | ✔ |
| 승인 요청(승인 후 실행 단계, 만료 시간 포함) | 켬(고정) | 켬 | 켬 | ✔ |
| 킬 스위치·자동화 정지(lease 상실 포함) | 켬(고정) | 켬 | 켬 | ✔(고정) |
| 토론 완료(심층 토론) | 켬 | 켬 | 끔 | — |
| 데이터 갱신(연기금 F13, 공시 감시) | 켬 | 끔 | 끔 | — |
| 일간·주간 리포트(F9) | 켬 | 끔 | 켬(요약+링크) | — |
| 키 만료·검증 실패·IP 변경 | 켬 | 켬 | 켬 | ✔ (admin에게는 공유 키, 구성원에게는 본인 키) |
| LLM 예산 80%·초과 | 켬 | 끔 | 켬 | — (admin만 보임) |

- **야간 방해 금지**: 켬/끔, 시간대(기본 23:00~07:00 KST). 켜져 있으면 "긴급" 열이 ✔인 것만 통과한다(PROJECT 10.1). 미국 장 시간대와 겹치므로 안내 문구를 붙인다.
- **Slack 내용 수준**: "수량·금액 포함"(기본 **끔** — 종목·방향·건수만) (PROJECT 7장 NOTIFY). relay를 붙이면 서버가 읽을 수 있는 최소 정보만 나간다는 안내.
- **테스트 알림**: 세 채널로 한 통씩.
- 알림 센터(11.3 "알림·승인 센터")는 별도 화면이고 여기서는 설정만 한다.

## 5. 회원 관리 · 공유 키 모달 (admin)

폭 760, 열 때 step-up(TOTP 6자리). 탭 둘.

### 5.1 회원 관리

**표**: 이름 · 역할 · 상태(활성/정지) · 마지막 로그인 · TOTP(등록/미등록) · 토스 키(등록/미등록 — 값·끝자리 없음) · 금융결제원(동의/미동의) · 디바이스 수 · 자동화(켬/끔 요약).

행 액션(모두 확인 창 + 감사 로그):

| 액션 | 효과 |
|---|---|
| 정지 / 해제 | 정지된 사용자는 로그인 불가, 자동화 즉시 정지(킬 스위치 사유 `USER`), 관심종목·설정은 보존 |
| 토스 키 삭제 | Keychain의 그 사용자 토스 키 삭제. 그 사용자는 다음 로그인 때 다시 입력(마법사 ③ 카드). 자동화 정지 |
| 금융결제원 동의 해제 | 사용자 토큰 삭제 |
| 디바이스 폐기(8단계) | 해당 디바이스 세션·키 폐기 |
| 데이터 파기 | 2단계 확인(이름 입력) 후 projection·설정·토론 삭제. `event_log`·`audit_log`·`broker_order`는 보존(DB_SCHEMA 3.5). 가족 공유 키 교체 안내 |
| admin 이관 | 다른 활성 사용자에게 admin 역할을 넘김. 본인은 구성원이 됨. 확인 창 두 번 [제안] |

**구성원 자리**: 남은 자리 N/3, "등록 코드 발급" → 코드를 **한 번만** 보여 주고 복사 버튼, 만료 24시간, 미사용 코드 목록·취소. 5번째 발급은 막힌다. 코드는 해시로만 저장(`registration_code`).

admin 자신에 대해서는 정지·삭제가 비활성이다(admin이 0명이 되지 않게).

### 5.2 공유 키

마법사 ②와 같은 목록(그룹 · 이름 · 필수/선택 · 상태 칩 · 끝 4자리 · 마지막 검증 · 응답 시간). 행 액션:

- **교체**: 값 입력 → "검증"(읽기 전용 호출, FIRST_RUN 5장 표) → 성공 시 저장·입력 칸 비움. 실패 값은 저장 안 함.
- **삭제**: 확인 창. 그 키에 의존하는 기능은 즉시 비활성(사유 표시), 자동화 중 LLM 전부 삭제 시 판단 보류 정책.
- **재검증**: 한 건 또는 전체(연결 확인 표와 같은 컴포넌트, 마법사 ④ 재사용).
- **공유 설정**(키 아님, `shared_setting`): SEC 연락처 이메일, KRX 이용 신청 만료일, LLM 프리셋(균형/품질/비용/로컬) → LLM 경로 편집은 설정 화면으로 링크, 설치 일일 예산·구성원별 몫·예비 예산·80% 알림, 공용 시세 수집에 쓰는 토스 키 = admin 본인 키(표시만).
- 키 상태 요약: 마지막 정기 검증(하루 1회) 결과, 실패한 키 강조.

값은 admin에게도 보이지 않는다(끝 4자리만). 모든 교체·삭제·재검증은 감사 로그.

## 6. 데이터와 저장

- `app_user`: `display_name`, `role`, `password_hash`, `totp_enrolled_at`, `status`, `extra_key_wrap`에 더해 **`email`(NULL 허용), `slack_user_id`(NULL 허용), `auto_stop_on_logout`(0/1)** 열을 둔다 → [DB_SCHEMA.md](DB_SCHEMA.md) 4장 수정.
- 알림 설정: `user_setting` 키 `notify.{kind}.{channel}`, `notify.quiet.enabled/from/to`, `notify.slack.includeAmounts`. 기본값은 코드 한곳(`UserSettingKey`).
- 개인 데이터 전송 허용: `user_setting` 키 `llm.allowPersonal.{provider}`.
- 공유 설정: `shared_setting`. 키 메타: `credential_meta`. 등록 코드: `registration_code`. 감사: `audit_log`(`PROFILE_CHANGED`, `PASSWORD_CHANGED`, `TOTP_REENROLLED`, `RECOVERY_REISSUED`, `KEY_SET/DELETE/VERIFY`, `MEMBER_SUSPENDED`, `REGISTRATION_CODE_ISSUED`, `DATA_PURGED`, `ADMIN_TRANSFERRED`, `CONSENT_REVOKED`).
- 로컬 API: `/me`(조회·수정), `/me/password`, `/me/totp`, `/me/recovery-codes`, `/me/credentials/toss`(교체), `/me/consents/kftc`, `/me/notifications`, `/admin/members/*`, `/admin/credentials/*`, `/admin/settings`. `/admin/*`은 admin 역할 + step-up 토큰 필수, `/me/*`는 본인 세션만.

## 7. 예외

| 상황 | 동작 |
|---|---|
| 구성원이 `/admin/*` 호출 | 403. 화면에도 메뉴 없음 |
| admin이 step-up 없이 회원 관리 열기 | TOTP 입력 카드 먼저. 5분 지나면 다시 |
| 토스 키 교체 검증 실패 | 옛 키 유지, 실패 사유 표시 |
| Slack 봇 토큰 없음 | Slack 열 비활성 + "admin이 봇 토큰을 등록해야 합니다" |
| 자기 자신 정지·삭제 | 버튼 비활성 |
| 마지막 admin 이관 실패 | 역할 변경은 트랜잭션 하나(둘 다 바뀌거나 둘 다 안 바뀜) |

## 8. 테스트

- 구성원 세션으로 `/admin/*` 403, admin 세션도 step-up 없이는 403(KEY_MANAGEMENT 8장).
- 비밀번호 변경은 현재 비밀번호 검증 없이는 거부. TOTP 재등록 후 옛 시드로 만든 코드 거부. 복구 코드 재발급 후 옛 코드 거부.
- 토스 키 교체: 검증 실패 시 Keychain 값 불변, 성공 시 옛 값 덮임, 응답·로그에 값 없음(표식 검색).
- 알림 설정: 방해 금지 시간대에 긴급이 아닌 Slack 알림 보류·긴급 통과(고정 `Clock`), 수량·금액 미포함 기본값.
- 등록 코드: 1회 사용, 24시간 만료, 4번째 구성원(5번째 사용자) 발급 거부. 정지 사용자 로그인 거부·자동화 정지.
- 데이터 파기 후 `event_log`·`audit_log`·`broker_order` 보존.

## 9. 결정 대기

1. **별도 로그인 ID 없이 표시 이름으로 로그인**(제안). 굳이 ID를 두려면 표시 이름과 분리한 `login_name` 열을 추가한다.
2. 이메일을 선택 항목으로(제안, relay 전까지 쓰임 없음).
3. admin 이관 기능(제안). 없어도 되지만 admin의 Mac 교체·부재를 생각하면 있는 편이 안전하다.
4. 패스키는 1단계에서 자리만(제안).
